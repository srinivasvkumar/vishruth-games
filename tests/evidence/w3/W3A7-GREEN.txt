## 5. Fix (the single production change)
────────────────────────────────────────────────────────────────────────────
src/scenes/MenuScene.ts — onExit() now resets this.started = false when
the menu stops being the active scene (19 insertions / 5 deletions,
mostly comments documenting the lifecycle):

    onExit(): void {
      // W3-A.7 (BUG-W2-1a re-arm): reset the start guard the moment the
      // menu stops being the active scene. The guard only needs to hold
      // WHILE THE MENU IS ACTIVE … Once the game scene is active, a later
      // onEnter() — returning from the game-over RESTART path — must
      // re-arm: the .catch() in startGame() alone never fires in the
      // normal flow because switchScene RESOLVES …
      this.started = false;
      this.detachKeydownHandler();
      this.cleanup();
    }

Lifecycle chain that makes the re-arm reliable:
  startGame() sets started=true → SceneManager.loadScene() calls
  menu.exit() (onExit: started=false, listener detached) → game.enter()
  → … death → gameover RESTART → SceneManager.loadScene('menu') calls
  menu.exit() (no-op, already inactive) → menu.enter() → onEnter() sees
  started===false → re-attaches keydown listener + re-enables START.
Rejection path unchanged: a rejected switchScene never exits the menu, so
.catch() still clears started and onEnter re-arms on the next enter.
Double-start guard preserved: started=true is set synchronously before the
async transition, so a rapid second Enter/click mid-transition is
suppressed (unit tests 15-16, unchanged, still pass).
