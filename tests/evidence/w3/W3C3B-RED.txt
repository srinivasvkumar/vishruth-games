  boundary (true 1 frame @ 60 fps = 16.67 ms). This is the rAF frame-cadence floor,

  Suspect allocation hot-spots in the input path (to be removed in GREEN):
    1. GameScene.onUpdate: new THREE.Vector3() for camTarget EVERY frame (1 alloc/frame).
    2. GameScene.onUpdate: getInputSystem().getInputState() returns {...this.keys}
       (a fresh object spread EVERY frame) + mouse object + gamepad arrays.
    3. InputSystem keydown/keyup handlers: e.key.toLowerCase() allocates a new string
       on every key event.
    4. InputSystem.clear(): this.keys = {} reallocates the map object.
    5. PhysicsSystem.applyForce/applyImpulse: new CANNON.Vec3() per call.

  These per-frame/per-event allocations add GC pressure that can stretch the rAF
  callback, widening the p95 tail. Removing them targets technique #1 (input handler
  overhead), #2 (input batching — keys read once at frame start), #4 (pre-allocated
  vectors), #5 (GC pauses). Technique #3 (physics before render) is already satisfied
  by Game.gameLoop ordering: input -> physics -> scene -> render in the same rAF.
