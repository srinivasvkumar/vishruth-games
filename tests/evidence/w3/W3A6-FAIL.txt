## Confirmed Defects
────────────────────────────────────────────────────────────────────────────

### BUG-W2-1a (re-confirmed in real browser): start-guard never re-arms
Severity: blocker

Symptom:
After a full run (menu -> game -> death -> gameover -> restart -> menu),
the #menu-start-button remains disabled. The user cannot start a new game.

Repro:
1. Boot to menu (button enabled, keydown wired)
2. Press Enter -> game starts, started=true, button disabled, keydown detached
3. Trigger death (CustomEvent 'player:death') -> GameOverScene
4. Click #gameover-restart-button -> switchScene('menu') -> MenuScene.onEnter()
5. onEnter() checks if (!this.started) — but started is STILL TRUE
   (it was set in startGame() and only reset if switchScene THREW,
   which it didn't since the game WAS registered this time)
6. Guard skips re-arm: button stays disabled, keydown stays detached
7. Both keyboard Enter and button click are dead -> second run impossible

Root cause (MenuScene.ts):
  startGame() line 351:  this.started = true;
  startGame() line 364:  this.started = false;  // only on switchScene() THROWS
  onEnter() line 71:     if (!this.started) { /* re-arm */ }

When the game IS registered (normal flow), switchScene() resolves,
started remains true forever, and onEnter() never re-arms.

The guard was written for the BUG-W2-1a case where switchScene REJECTS
because the 'game' scene is not yet registered — but in the normal
flow (game registered before start), the guard prevents ALL re-arming.

Impact:
  - S4 fails: page.click('#menu-start-button') times out 15s
  - S6 fails: same — second Enter after returning to menu is ignored
  - W2-1b fails: btnEnabled === false (expected true)

Evidence from Playwright page snapshot (W2-1b failure):
  - button "START" [disabled] [ref=e81] [cursor=pointer]
  (button present in DOM but disabled attribute set)

Fix direction (for game-dev, NOT a test fix):
Option A — reset started in onExit():
    protected onExit(): void {
      this.started = false;   // ADD
      this.detachKeydownHandler();
      ...
    }

Option B — reset started after switchScene succeeds in startGame():
    this.game.switchScene('game').then(() => {
      // scene is now active; the new scene's onEnter will re-arm
      // when the user returns to the menu
      // (started stays true until onExit resets it)
    });
    // AND add this.started = false to onExit()

Option C — track "am I in a game" via game.getState() rather than a
    local flag, and re-arm whenever the menu is entered and the game
    is not running.

Any fix must ensure:
  1. onEnter() re-arms the guard when returning to the menu
  2. The button becomes enabled again
  3. The keydown handler is re-attached
  4. The second run starts cleanly (score=0, level=1)

### D-A6-1 (documented, asserted as known-bad): GameOverScene does not
    read the level:start data payload
Severity: major (score display bug)

GameOverScene.setFinalScore() displays 0 even though GameScene.gameOver()
passes {score: N, highScore: M} in the switchScene data payload.
The data arrives at SceneManager.switchScene(sceneName, data) but
GameOverScene.onEnter() does not read it.

Confirmed in S3 test:
  - handoff data: {score: 150, highScore: 0}
  - display: "Final Score: 0"
  - mismatch: true (expected known defect still present at this commit)
